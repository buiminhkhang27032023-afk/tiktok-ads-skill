### 1. Cấu trúc Ads Manager (Campaign → Ad Group → Ad)
Học lúc: 2026-10-12 17:16 ICT

**Ba tầng chuẩn (Manual):**
- **Campaign**: mục tiêu (objective), tên, ngân sách chiến dịch (daily / lifetime / không giới hạn). Có thể bật Campaign Budget Optimization, split test; khai báo Special ad category nếu cần.
- **Ad Group**: placement, đối tượng, lịch chạy, optimization goal, phương thức giá thầu/bid. Mỗi campaign nhiều ad group để so sánh/tối ưu.
- **Ad**: creative (ảnh/video), tên hiển thị, profile, copy, CTA, tracking.

**Smart+ nâng cấp (4 tầng):** Campaign → Ad Group → Ad → Creative. Ad gói nhiều creative asset; Creative là từng video/ảnh/text riêng (Smart+ creative ID). Reporting/MMP chỉ hỗ trợ 3 tầng nên tầng Ad mới có thể không map đủ sang MMP.

**Kiểu tạo campaign:** Manual, Search, hoặc Smart+. Manual/Smart+ đã gộp một flow: full auto / bán auto / full manual.

**Thực dụng VN:**
- Đặt objective đúng ngay tầng Campaign (đổi objective Reservation sẽ reset ad group).
- Test nhiều creative ở tầng Ad; giữ biến số audience/bid ổn định ở Ad Group để đọc được tín hiệu.
- Nếu dùng Smart+: lưu ý báo cáo 4 tầng vs MMP 3 tầng khi đối soát agency/đối tác đo lường.

### 2. Mục tiêu chiến dịch (Objectives)
Học lúc: 2026-10-12 17:18 ICT

**3 nhóm objective (Help Center cập nhật 04/2025):**
- **Awareness (Nhận biết):** Reach — hiển thị tới nhiều người nhất.
- **Consideration (Cân nhắc):** Traffic (đưa người tới web/app), Video views (lượt xem từ người dễ chú ý), Community interaction (follow, xem profile/page, quảng bá LIVE), Branded Mission (tương tác qua hợp tác creator).
- **Conversion (Chuyển đổi):** App promotion (cài app + hành động trong app), Lead generation (thu lead), Sales (bán hàng từ TikTok Shop, website, app — đã gộp Web Conversions/Catalog/Product Sales cũ).

**Điểm thực dụng:**
- Chọn objective theo hành động muốn người xem làm; tối ưu thật sự nằm ở **optimization goal + bid** tầng Ad Group.
- Traffic có goal **Landing Page View**: chỉ tính khi click và trang đích tải xong → traffic chất lượng hơn Click thường.
- Lead gen: dùng **Instant Form** (form ngay trong TikTok, không cần web) hoặc trang lead riêng (khi đó nên cài cả Pixel + Events API). Event hay dùng: submit form, complete registration, contact, subscribe...
- Bán hàng web: TikTok gợi ý chạy Sales kết hợp Traffic; e-commerce có thể kết hợp Catalog Ads; Smart+ để tự động hóa.
- App promotion: tối ưu cài đặt, in-app event, hoặc **value (ROAS)**; hỗ trợ retargeting user cũ.
- Bán TikTok Shop ở VN: objective Sales → nguồn TikTok Shop (sẽ đào sâu ở mục GMV Max).

### 3. Pixel / Events API
Học lúc: 2026-10-12 17:24 ICT

**TikTok Pixel (client-side):**
- Đoạn code gắn trên website để gửi event (xem trang, xem SP, thêm giỏ, mua…) về TikTok.
- Dùng để: đo traffic, đo hiệu quả campaign, tối ưu & tìm khách mới.
- Thu thập qua trình duyệt: thông tin ad/event, timestamp, IP (địa lý), User Agent (thiết bị/OS/trình duyệt), cookie, metadata & click nút.
- Cookie bên thứ ba bật mặc định; cookie first-party tùy chọn — kết hợp cả hai + Advanced Matching giúp đo & tối ưu tốt hơn.
- Kiểm tra bằng Pixel Helper trước khi chạy ads.

**Events API (server-to-server):**
- Gửi dữ liệu marketing từ server của bạn → TikTok (web, app, offline/CRM).
- Bắt buộc có Pixel **hoặc** Events API trước khi chạy objective Web Conversions.
- Lợi ích: bắt conversion bị mất vì trình duyệt/chặn cookie; gom nhiều kênh vào 1 API; kiểm soát dữ liệu chia sẻ; bền vững hơn khi ecosystem thay đổi (cookieless).

**Setup khuyến nghị (web):**
1. Chạy **Pixel + Events API cùng lúc** + **Event Deduplication** (dùng cùng `event_id` hai đầu; TikTok gộp trong ~48 giờ).
2. Event & parameter giống nhau trên cả hai kênh theo full funnel (ViewContent → AddToCart → Purchase…).
3. Truyền đủ **match keys** (email/phone đã hash, v.v.) để tăng match rate → tối ưu & audience tốt hơn.
4. Events API 2.0 cần access token (tạo qua developer portal).

**Thực dụng VN:**
- Shop bán qua website: cài Pixel trước, gắn event Purchase có value + currency; rồi bổ sung Events API (partner hoặc in-house).
- Lead gen Instant Form không cần Pixel web; nếu lead về landing riêng thì Pixel + Events API.
- Đừng chỉ tin số trên Ads Manager nếu chưa dedupe — dễ đếm đôi conversion.

**Nguồn (chính thức):**
- https://ads.tiktok.com/help/article/tiktok-pixel
- https://ads.tiktok.com/help/article/events-api
- https://ads.tiktok.com/resources/help/article/getting-started-events-api

### 4. Target / Audience (đối tượng)
Học lúc: 2026-10-12 17:30 ICT

**Cấu hình ở tầng Ad Group.** Các chiều chính (Help Center cập nhật ~10/2026):
- **Demographics**: tuổi, giới tính, ngôn ngữ, vị trí (location theo thị trường).
- **Audience Targeting**: Interest & Behavior, Custom Audience, Lookalike.
- **Advanced / Device**: loại thiết bị, hệ điều hành, v.v.
- **Smart Targeting**: mở rộng tự động tới người dễ hoàn thành mục tiêu (không ghi đè age/location cứng).

**Logic chọn:**
- Trong cùng 1 chiều = **OR** (Beauty hoặc #makeup → người thỏa 1 trong hai).
- Giữa các chiều khác nhau = **AND** (Nữ + 25–44 → phải thỏa cả hai).

**Interest vs Behavior (theo Targeting Guide):**
- Interest: sở thích dài hạn / cộng đồng (beauty, food…).
- Behavior: hành động gần đây (xem/like/share video liên quan ~15 ngày; follow creator ~90 ngày).

**Custom Audience (tối thiểu ~1.000 user matched để dùng trong ad group):**
- Upload file khách, Pixel/app activity, tương tác TikTok, hoặc partner.
- Dùng để: retarget, loại trừ khách mới mua, làm nền Lookalike.

**Lookalike:** TikTok tìm người giống seed Custom Audience; hẹp = chính xác hơn, rộng = reach lớn hơn — hay dùng để prospect sau khi có seed chuyển đổi.

**Best practices (chính thức TikTok):**
- Bắt đầu **broad**: audience “fairly broad” (>80% potential users trong nước) theo TikTok trung bình CPA thấp hơn ~15% và conversion rate cao hơn ~20% so với hẹp (số TikTok công bố).
- Bật **Smart Targeting** khi dùng Audiences hoặc Interest & Behavior.
- Tránh audience quá hẹp → khó thoát learning phase, creative mau mệt.
- Smart+ mặc định auto targeting; chỉ Switch to custom khi cần kiểm soát tay.

**Thực dụng VN:**
- Prospecting: location VN + tuổi phù hợp sản phẩm, ít interest cứng; bật Smart Targeting; ưu tiên creative.
- Retarget: Custom từ Pixel (ViewContent/AddToCart) hoặc engagers; exclude Purchase gần đây nếu đã bán.
- Scale: Lookalike từ purchaser/seed tốt; không siết zip/huyện trừ khi có lý do (cửa hàng địa phương).
- Shop TikTok Shop/GMV Max thường để hệ thống tự tìm audience — ghi nhớ khi học GMV Max.

### 5. Spark Ads
Học lúc: 2026-10-12 17:37 ICT

**Là gì:** định dạng native dùng **bài post organic** làm quảng cáo; mọi view, like, comment, share, follow khi boost đều cộng vào bài gốc (hiệu ứng kéo dài sau campaign).
- Dùng post của chính tài khoản mình, hoặc post của **creator khác khi họ cấp quyền** (authorization code; có thể tùy chỉnh thời hạn ủy quyền).

**Hỗ trợ objective:** Auction: Reach, Traffic, Video Views, Community interaction, App promotion, Conversions, Lead gen, Sales. Reach & Frequency: Reach, Traffic, Video Views.

**Thông số quan trọng:**
- Không giới hạn tỉ lệ/độ phân giải/định dạng/dung lượng; video tối đa **10 phút**.
- Caption có thể để trống; được tag tài khoản, emoji, hashtag.
- Tên hiển thị & text lấy theo post gốc, không sửa được trong Ads Manager (nhưng có tính năng text edit cho Spark push khi set up — xem lại UI thực tế).
- Post bị ban organic → bị từ chối luôn trong Ads Manager.
- Muốn xóa video khỏi tài khoản organic phải **hủy ủy quyền Spark** trước.
- Tối đa 10.000 Spark Ads / tài khoản Ads Manager.

**Khác non-Spark:** Spark cho bấm avatar/tên/vuốt trái → vào **profile**, bấm "+" để follow, bấm nhạc → trang nhạc; chỉ CTA + caption dẫn tới landing page. Non-Spark: CTA, avatar, tên, caption, vuốt trái đều dẫn tới landing/app.
- Metric riêng: paid followers, paid profile visits, music clicks, anchor clicks/anchor click rate; paid likes/shares/comments tính trong 1 ngày sau khi xem ad.

**Thực dụng VN:**
- Tìm video organic (của shop hoặc KOC) đang có tương tác tốt → xin code ủy quyền → Spark để tận dụng social proof, đồng thời nuôi kênh.
- Đặt thời hạn ủy quyền vừa đủ thời gian chạy campaign khi làm với KOC (theo tính năng TikTok mô tả là để "giảm chi phí").
- Vì Spark dẫn traffic một phần về profile, khi đo chuyển đổi cần nhìn cả paid profile visits/followers, không chỉ click CTA.

**Nguồn (chính thức):**
- https://ads.tiktok.com/help/article/spark-ads

### 6. GMV Max / TikTok Shop
Học lúc: 2026-10-12 17:39 ICT

**Là gì:** loại campaign tự động của TikTok Shop Ads, tối ưu GMV tổng (paid + organic + affiliate). Hệ thống tự chọn sản phẩm, creative, audience, placement; mình chỉ chọn **sản phẩm, ROI mục tiêu, ngân sách ngày**. Có 2 loại: **Product GMV Max** và **LIVE GMV Max**.
- Từ **07/2025**: GMV Max là loại campaign **mặc định và duy nhất** khi chọn Sales + đích TikTok Shop. Không tạo/sửa/nhân bản được LIVE Shopping Ads, Product Shopping Ads, Video Shopping Ads kiểu cũ với đích Shop (campaign cũ vẫn chạy). Video Shopping Ads vẫn dùng được nếu đích là Showcase; LIVE Shopping Ads vẫn tạo được bằng TikTok identity.
- Nút "Upgrade now" chuyển campaign cũ sang GMV Max, lấy ROI lịch sử làm ROI mục tiêu.

**Điều kiện chạy (checklist khi không tạo được):**
- Business Center đã kết nối với Shop (nếu shop ở nhiều BC, chọn BC chứa cả tài khoản quảng cáo và TikTok account sẽ dùng).
- Seller tự chạy: cần quyền Admin hoặc Advertising Manager của shop. Agency: cần quyền ad promotion của shop + được seller cấp GMV Max authorization.
- Có quyền operator/admin tài khoản quảng cáo, và tài khoản đã được ủy quyền chạy GMV Max (nút "Create GMV Max ads" xám là do thiếu cái này).
- Quốc gia hoạt động của shop: Indonesia, Malaysia, Philippines, Thái Lan, **Việt Nam**, Singapore, Mỹ.

**Cách tạo nhanh:** Ads Manager → GMV Max → chọn Shop → Create GMV Max ads → Promote products → chọn tất cả SP hoặc +Add product → đặt ROI, ngân sách, lịch → Publish (chạy liên tục sau giờ bắt đầu).

**Best practice chính thức (công thức TikTok đưa ra):**
- ROI mục tiêu gợi ý = GMV non-LIVE lịch sử ÷ chi phí quảng cáo lịch sử. ROI thấp hơn → phân phối & GMV nhiều hơn; ROI cao → dễ bị hạn chế chi tiêu. Theo ROI hệ thống gợi ý hoặc đặt thấp hơn một chút.
- Ngân sách gợi ý = 2 × GMV non-LIVE lịch sử ÷ ROI mục tiêu. Giữ mức tiêu ngân sách **dưới 80%**, tăng ngân sách khi hiệu quả tốt lên.
- **Giữ nguyên ROI ít nhất 3 ngày trọn** trước khi chỉnh (hệ thống tối ưu theo ngày, chỉnh liên tục làm gián đoạn học).
- Shop mới chưa có dữ liệu: dùng ROI & ngân sách gợi ý trên giao diện.
- Đưa càng nhiều sản phẩm càng tốt; đánh giá bằng GMV **tổng shop** để thấy phần tăng thêm.
- Creative: bật **Auto-select videos** (tự quét mọi video hiện tại và tương lai, không giới hạn); đưa cả **video affiliate** (thường hiệu quả hơn); đăng nhiều video có **gắn product anchor**; liên kết thêm TikTok account và thêm Spark Ads post vào Creative Library.

**Thực dụng VN:** bán trên TikTok Shop thì mặc định đi GMV Max; việc chính của người chạy là (1) xử lý đúng quyền BC/Seller Center, (2) đặt ROI dựa trên số lịch sử rồi để yên 3 ngày, (3) nuôi nguồn video: kênh shop + KOC/affiliate gắn giỏ hàng.

### 7. Smart+ (campaign tự động bằng AI)
Học lúc: 2026-10-12 17:45 ICT

**Là gì:** campaign tự động hóa target, tối ưu, giá thầu, placement và creative. Mình chỉ đưa KPI, creative, quốc gia + ngôn ngữ. Áp dụng cho Sales, App Promotion, Lead Generation, Traffic.

### 8. Giá thầu / Bidding strategies
Học lúc: 2026-10-12 17:47 ICT

**Cách TikTok xếp hạng ads:** dựa trên bid của bạn + độ liên quan với người dùng. Bid strategy bảo hệ thống đấu giá thế nào trong auction (tầng Ad Group, mục Bidding & Optimization).

**2 chiến lược chính (Help Center cập nhật 09/2026):**
1. **Target Cost per Result** (goal-based; glossary còn gọi Cost Cap): tối ưu để CPA trung bình gần mức bạn đặt. CPA thực tế có thể hơi cao/thấp hơn target. Mặc định với Reach & Video views; có suggested bid + reach estimator. Với Conversions chỉ hiện khi Optimization Goal = Conversion.
2. **Maximum Results** (spend-based; còn gọi Maximum Delivery / Lowest Cost trong tài liệu cũ): cố tiêu ngân sách để lấy **nhiều kết quả nhất** trong khung ngân sách — không giữ CPA cố định, CPA dao động theo auction là bình thường.

**Billing event hỗ trợ (tóm tắt bảng chính thức):** oCPM, CPC, CPM, CPV tùy objective. Objective hỗ trợ: Traffic, Reach, Video Views, App Installs, Conversions, Lead Generation…; Maximum Results còn Catalog Sales.

**Best practice chính thức (08/2026):**
- **Maximum Results:** dùng khi cần volume (promo, flash sale) và chưa có CPA cứng. Ngân sách ngày ≈ **10× CPA trung bình 7 ngày gần nhất** để thoát learning. Sau learning (conversion): tăng ngân sách ad group **≥20%/lần** (CPA thường tăng theo). Lo sợ CPA cao khi scale → hybrid: chuyển sang Target Cost per Result + bid chấp nhận được.
- **Target Cost per Result:** dùng khi phải giữ CPA quanh mục tiêu. Ngân sách ≥ **10× bid CPA**. Không tiêu hết ngân sách → tăng bid **≥20%**. Khi tăng budget lớn, dùng Target Cost để giảm biến động. Dùng suggested bid để đủ tỉ lệ bid/budget. Reach/Video view auction: đặt bid cao nhất bạn chấp nhận ngay (cao ngay tốt hơn bắt đầu thấp rồi tăng dần). Đừng giảm bid ngay khi CPA/ROAS lệch — chờ hệ thống điều chỉnh; giảm sớm dễ làm spend tụt mạnh.
- FAQ cũ còn nhắc **Bid Cap** (ceiling cứng từng lần đấu) và tên Lowest Cost — ưu tiên tên trên Help Center mới.

**Thực dụng VN:**
- Campaign mới / thiếu data: Maximum Results + ngân sách đủ 10× CPA ước tính, tập trung creative.
- Đã biết CPA chấp nhận được (VD lead/đơn): chuyển Target Cost per Result, giữ ổn định vài ngày trước khi chỉnh lớn.
- Scale budget: tăng từng bước ≥20%, cân nhắc khóa CPA bằng Target Cost; đừng chỉnh bid liên tục trong learning.

### 10. A/B test (Split Testing)
Học lúc: 2026-10-12 18:02 ICT

**Là gì:** công cụ Split Testing trong TikTok Ads Manager để so sánh **hai phiên bản** (control vs test). Hệ thống chia audience thành **hai nhóm bằng nhau**, mỗi nhóm chỉ thấy một ad group/campaign → tránh “squeezing” (hai bên tranh cùng audience). Chỉ công bố winner khi kết quả **có ý nghĩa thống kê** (confidence **90%**).

**Biến có thể test (Help Center cập nhật 01/2026):**
- Targeting, Placement, Bidding and Optimization, Budget Strategy
- Creative Assets, Catalog, Creative
- **Custom** (cấp campaign, kết hợp nhiều biến)
- **Smart+**

**Cách tạo (tóm tắt):**
1. Campaign → Create → chọn objective → bật toggle **Create a split test**.
2. Setup Ad group (control) + Ad.
3. Tab Split test: chọn biến, **Key metric** (metric hệ thống dùng để so sánh), setup Test ad group → Complete.
4. Lịch test **ít nhất 7 ngày** để đủ mẫu hữu ích.

**Campaign-level (blog TikTok):** ngoài ad group, có thể so sánh hai campaign (cấu trúc, creative strategy, thậm chí objective khác nhau). Với Smart+: hệ thống có thể tự sinh Smart+ từ manual campaign để so sánh công bằng. Audience A chỉ thấy Campaign A, B chỉ thấy B; winner theo significance 90%.

**Lợi ích chính thức:** tối ưu có căn cứ; kết quả khoa học; không để hai biến thể tranh audience; kết thúc test có thể **1 click** tiếp tục chạy nhánh thắng rồi test tiếp để tinh chỉnh.

**Thực dụng VN:**
- Mỗi lần chỉ đổi **1 biến** (trừ Custom/multi có chủ đích) — ví dụ hook video, broad vs interest, Maximum Results vs Target Cost, Smart+ vs manual.
- Chọn Key metric khớp mục tiêu thật (CPA / conversions / CTR…); đừng kết luận sớm trước 7 ngày hoặc khi chưa có winner 90%.
- Sau khi có winner: scale nhánh thắng; test tiếp biến kế tiếp (creative → bid → target).
- Case MaryRuth's (TikTok Fundamentals blog): split test Smart Targeting → CTR +24%, CPA −31%, conversions +33% so với control (số TikTok công bố).

### 11. Chỉ số CTR / CPA / ROAS
Học lúc: 2026-10-12 18:06 ICT

**Định nghĩa chính thức (Ads Manager + Seller Center + guide TikTok):**
- **CTR (click-through rate):** % impression dẫn tới destination click = clicks (destination) ÷ impressions. CTR cao = creative + message đang “ăn” đúng người; thấp → xem lại hook/offer (Product Advertising Guide). Seller Center: CTR = % impressions có destination click.
- **CPA / Cost per conversion / Cost per acquisition:** tiền quảng cáo trung bình cho **một conversion** (theo optimization event bạn chọn). Công thức: Cost ÷ Conversions. Help Center gọi **Cost per conversion**; tài liệu One Project còn ghi CPA = average amount spent per conversion.
- **ROAS (return on ad spend):** doanh thu từ ads ÷ chi phí ads. Ví dụ TikTok đưa: kiếm $4 trên mỗi $1 ads → ROAS = 4 (hay 4×). Page events còn có metric **Payment completion ROAS (page)**.

**Các chỉ số liên quan hay nhìn cùng:**
- **CPC (destination):** chi phí trung bình mỗi click tới đích.
- **CVR:** % conversion trên impressions; **CVR (clicks):** % conversion trên destination clicks — giúp tách vấn đề ad vs landing.
- **CPM:** chi phí / 1.000 impressions.
- Attribution: Cost per CTA Conversion / CTA Purchase (click-through attribution) vs VTA (view-through) — đừng so CPA nếu cửa sổ attribution khác nhau.

**Cách đọc thực dụng (theo guide TikTok, không bịa benchmark):**
1. **CTR** → creative / targeting có kéo click không. CTR cao mà conversion kém → nghi landing/offer/Pixel, không đổ lỗi creative ngay.
2. **CPA** → hiệu quả chi phí lấy 1 kết quả. Product Guide: nếu CPA cao hơn biên lợi nhuận thì phải đổi chiến lược.
3. **ROAS** → ads có “trả lại” doanh thu không (đặc biệt e-com / Shop). Track efficiency bằng CPA + ROAS; track reach/engagement bằng impressions + CTR; cần cả hai để scale bền.
4. Pixel + Events API: TikTok công bố trung bình bắt thêm **19%** event và CPA cải thiện **~15%** so với chỉ dùng một (Performance Fundamentals — số TikTok, không tự đo).
5. Attribution window mặc định Seller Center Ads Dashboard (nhiều nước gồm **VN**): **7 ngày post-click hoặc 1 ngày post-view** trừ khi tùy chỉnh. Seller Center ghi doanh thu theo ngày bán; Ads Manager theo cửa sổ attribution → số có thể lệch.

**Thực dụng VN:**
- Custom columns trong Campaigns: Cost, CTR, CPC, Cost per conversion, Conversions, ROAS (hoặc Gross revenue / Payment completion value tùy objective).
- Shop: nhìn ROAS + Cost per purchase trong Seller Center; đối chiếu Ads Manager trước khi kết luận “lỗ/lãi”.
- Tối ưu theo tầng: CTR thấp → đổi hook/creative; CTR ổn + CPA cao → bid/landing/audience; ROAS tốt + còn room → tăng budget (học ở mục scale).

### 12. Scale ngân sách (Budget scaling)
Học lúc: 2026-10-12 18:14 ICT

**Hai kiểu ngân sách (Help Center cập nhật 07/2026):**
- **Daily budget:** mức chi trung bình/ngày — hợp campaign chạy dài, theo dõi/chỉnh từng ngày.
- **Lifetime budget:** tổng chi trong cả kỳ chạy — hợp launch, promo, sự kiện có ngày kết thúc.
- Sau khi live **không đổi được** Daily ↔ Lifetime; chỉ tăng/giảm số tiền trong cùng kiểu.
- Khi ad group hết ngân sách → delivery pause; tăng budget hoặc kéo dài lịch để chạy lại.
- Ngân sách Campaign **không được thấp hơn** Ad Group (dễ lỗi delivery).

**Ngưỡng tối thiểu (USD, tài liệu chính thức):**
- Daily: Campaign > $50; Ad group > $20.
- Lifetime Ad group = số ngày (kể cả ngày đã qua) × mức daily tối thiểu (VD 31 ngày × $20 = $620).

**Quy tắc tăng budget theo Learning Phase (About Budget):**
- Đang **learning**: mỗi lần tăng **≤ 40%**.
- Đã **thoát learning**: mỗi lần tăng **≤ 30%**.
- Không chỉnh dày hơn **mỗi 2 ngày**.
- Learning thường ổn định hơn sau ~**25 kết quả** hoặc **~7 ngày** (About Learning Phase, 06/2026). Trong learning: tránh pause, tránh edit lớn (retrigger learning), budget/creative bất hợp lý.

**Scale kèm bid (Best practices bidding, đã học mục 8):**
- Maximum Delivery sau learning (conversion): tăng budget ad group **≥ 20%/lần** — CPA thường tăng theo.
- Lo CPA vượt trần khi scale → hybrid: chuyển **Target Cost / Cost Cap** + bid chấp nhận được.
- Cost Cap: budget ≥ **10×** bid CPA; spend thấp → tăng bid ≥ 20%.

**CBO — Campaign Budget Optimization:**
- Một ngân sách campaign dùng chung mọi ad group; tối ưu volume/conversion ở **cấp campaign**.
- Best practice: đặt đúng budget mục tiêu; budget ad group cover **≥ 5×** target CPA; **3–5** ad group active + **2–3** creative/group (CBO kém hiệu lực nếu chỉ 1 ad group).
- Chỉnh tối ưu: chờ **≥ 3 ngày** hoặc **≥ 50 conversions**; mỗi lần chỉnh giữ trong **~30%** daily budget hiện tại. Mọi ad group cùng Optimization Goal.

**Smart+ Web (đã học mục 7):** tiêu đều ≥ **90%** daily → thử tăng budget tối đa **30%**. Khởi đầu lý tưởng **10–30×** CPA lịch sử.

**GMV Max (đã học mục 6):** giữ mức tiêu **< 80%** ngân sách; hiệu quả tốt mới tăng; ROI giữ ổn ≥ 3 ngày trước khi chỉnh.

**Thực dụng VN:**
1. Chỉ scale khi đã thoát learning (hoặc đủ ~25 conversion/7 ngày) và CPA/ROAS còn chấp nhận được.
2. Tăng từng bước 20–30% (learning ≤40%), cách nhau ≥ 2 ngày; đừng nhân đôi overnight.
3. Scale volume lớn: Maximum Delivery + tăng budget; cần khóa CPA → Cost Cap/Target Cost khi tăng.
4. Nhiều ad group cùng objective: cân nhắc CBO + 3–5 nhóm + creative đa dạng.
5. Shop: scale GMV Max bằng tăng budget khi spend <80% và ROI ổn; không chỉnh ROI liên tục.

### 13. Chính sách & lý do bị từ chối (Ad Review)

4. **Nội dung nhạy cảm:** chính trị, tôn giáo, văn hóa nhạy cảm; cảnh gợi dục / khiêu khích; hình ảnh gây sốc/sợ.

### 15. Đào sâu: Attribution window (cửa sổ phân bổ chuyển đổi)
Học lúc: 2026-10-12 18:36 ICT

**Khái niệm:**
- **CTA (Click-through):** người dùng click ad rồi chuyển đổi trong khoảng thời gian cho phép.
- **VTA (View-through):** người dùng xem ad, không click, nhưng sau đó vẫn chuyển đổi.
- **EVTA (Engaged view-through, dành cho app/SAN):** xem ad có tương tác (engaged view) rồi chuyển đổi.
- Mỗi chuyển đổi chỉ được ghi cho **1 điểm chạm** (click, view hoặc engaged view).

**Tùy chọn (web/app qua Pixel, Events API):**
- CTA: 1 / 7 / 14 / 28 ngày. VTA: Tắt / 1 / 7 ngày.
- Mặc định: **7 ngày click + 1 ngày view**.
- App qua Self-Attributing Network (SAN): CTA 1 hoặc 7 ngày; EVTA 1 hoặc 7 ngày; VTA tắt hoặc 1 ngày.
- Cài ở tầng **Ad Group** (Bidding and Optimization → Attribution settings). **Không đổi được sau khi publish**, muốn đổi phải tạo ad group mới.
- Event count: **Every** (đếm mọi lần, dùng cho AEO purchase và VBO tối ưu giá trị) hoặc **Once** (đếm 1 lần, cho install và AEO không phải purchase).

**Khuyến nghị của TikTok:**
- Nên **bật VTA**: cho TikTok thêm dữ liệu chuyển đổi để tối ưu. TikTok nói bật cả CTA + VTA giúp thoát learning phase nhanh hơn tới 113% và chi tiêu ổn định hơn (số liệu nội bộ TikTok).
- Sản phẩm cân nhắc lâu (giá cao, dịch vụ): kéo dài CTA hơn 7 ngày và VTA hơn 1 ngày.
- Nghiên cứu nội bộ TikTok: cửa sổ view tối ưu khác nhau theo ngành (Travel ~16 ngày, CPG ~19 ngày, Gaming ~3 ngày); hiện tối đa 7 ngày view, TikTok khuyên dùng 7 ngày view.

**Thực dụng VN:**
- Cửa sổ trong Ads Manager chỉ đổi **báo cáo trên TikTok**, không đổi báo cáo MMP (AppsFlyer, Adjust…) hay GA4. Nên để cùng cửa sổ giữa các bên để giảm chênh lệch số liệu.
- Khi so ROAS TikTok với số đơn thực tế/GA4 (last click), nhớ TikTok tính cả view-through, nên số trên TikTok thường cao hơn. Đừng kết luận "TikTok báo ảo" khi chưa so cùng cửa sổ.
- Đặt cửa sổ ngay từ đầu cho chuẩn, vì không sửa được sau khi publish. Khi so sánh A/B giữa các ad group, giữ cùng cửa sổ.
- Hàng giá thấp, mua bốc đồng (mỹ phẩm, đồ gia dụng nhỏ): mặc định 7 click/1 view thường đủ. Hàng giá cao (khóa học, nội thất, BĐS lead): cân nhắc 14–28 ngày click, 7 ngày view.

### 16. Đào sâu: LIVE GMV Max
Học lúc: 2026-10-12 18:41 ICT

**Là gì:** campaign Shop Ads tự động, tối ưu traffic vào phòng LIVE để tăng GMV tổng của buổi livestream (paid + organic). Tạo được ở Ads Manager hoặc Seller Center. Mục tiêu tối ưu = **LIVE ROI** = GMV tổng liveroom ÷ chi tiêu ads.

**2 loại creative (hệ thống tự phân bổ, không chọn một mình):**
- **Video-to-LIVE:** dùng video từ tài khoản TikTok đã kết nối để kéo người vào phòng LIVE.
- **LIVE-to-LIVE:** dùng chính buổi livestream đang chạy để kéo thêm viewer vào cùng phòng.

**Điều kiện / giới hạn (VN nằm trong list):**
- Shop kết nối Business Center; quyền Admin hoặc Advertising Manager của shop (agency cần GMV Max authorization).
- Chỉ **1 ad account chính** / shop (primary trong Seller Center) được chạy GMV Max. Đổi primary → account cũ mất quyền, campaign GMV Max cũ bị pause.
- Đang chạy LIVE Shopping Ads hoặc LIVE GMV Max khác → phải tắt trước khi tạo mới.
- Có ≥ 1 LIVE GMV Max active trên primary account → mọi **LIVE Shopping Ads** của official TikTok account shop bị pause (mọi ad account). Hết campaign: **không** tự bật lại — phải bật tay.
- Disconnect TikTok account khỏi shop / BC / ad account → LIVE GMV Max có thể bị pause.
- Thị trường: Indonesia, Malaysia, Philippines, Thái Lan, **Việt Nam**, Singapore.

**Cách tạo (Ads Manager):** GMV Max → chọn Shop → Create GMV Max ads → **Promote LIVE** → chọn TikTok account có LIVE → đặt LIVE ROI target + ngân sách ngày + lịch → Publish.

**Attribution (quan trọng khi đọc số):**
- Mọi conversion paid **và** organic **trong phòng LIVE** được gán cho LIVE GMV Max khi campaign đang chạy.
- Đơn từ **mọi shop** trong cùng buổi LIVE cũng được gán (kể cả shop không dùng để setup campaign).
- Rời LIVE rồi mới đặt đơn → **không** gán cho LIVE GMV Max.
- Product GMV Max: đơn SP trong campaign được gán dù không xem/click ad (trong cửa sổ ~1 ngày theo ví dụ TikTok); mua SP khác hoặc sau cửa sổ → không gán.

**Best practice chính thức (cập nhật ~09/2026):**
- Chạy tối thiểu **3 ngày** (không cần liên tục). Phiên bán > **3 giờ** thường tăng GMV/session nhanh hơn; khuyến nghị livestream **> 8 giờ/ngày**.
- Giữ giờ LIVE ổn định giữa các ngày; dùng màn hình LIVE rõ brand, nền thật, trả lời lo ngại khách.
- ROI & budget: theo gợi ý hệ thống hoặc budget **2–3×** ads LIVE lịch sử. Budget chỉ tiêu hết khi gần đạt ROI target. Có ROI protection (hoàn nếu ROI dưới ngưỡng khi làm đúng guideline).
- Ngày 1 spend chậm → hạ ROI target; spend nhanh (thường = đang tốt) → tăng budget hoặc tăng ROI.
- Chọn profile LIVE mạnh (~**$1000 GMV LIVE / 7 ngày** gần nhất theo TikTok).
- Video-to-LIVE: giữ nguồn creative **50–70 video** mỗi đợt hoặc **5–10 video mới/ngày**; video ngắn, CTA rõ, nhấn promo/hero product; chọn tối đa **10 Preferred videos** khớp buổi LIVE (cập nhật mỗi buổi); đọc video reporting để quay tiếp.

**Thực dụng VN:**
1. Shop LIVE thường xuyên: dùng LIVE GMV Max thay LIVE Shopping Ads cũ; nhớ chỉ 1 primary ad account.
2. Trước giờ LIVE: upload/chọn Preferred videos gắn promo buổi đó; đừng để thư viện trống.
3. Đặt ROI theo lịch sử LIVE (không theo Product GMV Max), giữ ổn định ít nhất vài ngày; chỉ hạ ROI nếu spend quá chậm.
4. Khi đọc ROI Ads Manager: nhớ số gồm cả organic trong phòng — so với GMV thực tế phòng LIVE, không so last-click web.
5. Tắt campaign xong nhớ kiểm tra LIVE Shopping Ads cũ nếu vẫn muốn chạy tay.

| Phạm vi | Tất cả affiliate post; bật một lần | Mỗi post một video code riêng gửi seller |
| Dùng trong ads | GMV Max / VSA → chọn **Affiliate Post** làm video source; hiện mọi post đã authorize | Thêm bằng video code (Spark-style) |
| Đổi SP khác link trong post? | **Không** — chỉ seller sở hữu SP gắn trên post mới dùng được link đó | **Có** — có thể gắn SP khác |
| Khi mất quyền / mất link organic | Ads **tự pause** nếu: tắt mass auth, hết collaboration, hoặc post mất product link organic | Ads **chạy tiếp** tới khi video code hết hạn |

**Lưu ý vận hành quan trọng:**
- **Không đổi được product link** trong affiliate post khi dùng mass ACA.
- Collaboration kết thúc → ads dùng creative đó **pause**.
- Cùng một post có thể được authorize bằng **cả** mass + video code.
- Dù mass hay code: đơn từ ad dùng affiliate post **vẫn có thể** tính commission cho creator.
- Khi đã bật mass: creator vẫn cần gửi video code nếu post **không có product link**, hoặc có link nhưng **không** thuộc affiliate collaboration.

**Báo cáo:** Seller Center → Ads × Affiliate: so organic vs ads; Gross revenue có thể ghi **cả Ads & Affiliate** khi dùng affiliate post trong ads — đừng cộng đôi khi đối soát agency.

**Thực dụng VN (Shop + GMV Max):**
1. Nuôi Open Collaboration ổn định với KOC có video bán tốt; nhờ họ bật **mass authorization** để GMV Max tự kéo creative (đã học mục 18: ACA là một nguồn creative).
2. Video “ngon” nhưng chưa có giỏ / chưa collaboration: xin **video code** riêng.
3. Theo dõi Ads × Affiliate trước khi kết luận “ads lỗ” — ROI GMV Max vốn gồm organic + affiliate cùng SP.
4. Khi KOC hết contract: kiểm tra campaign pause; chuẩn bị video shop/Spark thay thế trước.
5. Ưu tiên creator đã gắn đúng SP shop mình (mass không cho đổi link).

### 27. Đào sâu: Keyword match types (Search Ads)
Học lúc: 2026-10-12 22:08 ICT

**Là gì (Help cập nhật 07/2025):** match type bảo TikTok **query tìm kiếm phải khớp keyword đến mức nào** thì ad mới được vào auction trên Search Results Page.

**3 loại + cú pháp:**
| Match | Cú pháp | Logic |
| --- | --- | --- |
| **Broad** | gõ thường (`keyword`) | Query **liên quan** keyword → reach cao nhất, relevance thấp nhất |
| **Phrase** | `"keyword"` (dấu ngoặc kép) | Query phải chứa **ý nghĩa** keyword (rõ hoặc ngầm) |
| **Exact** | `[keyword]` (dấu ngoặc vuông) | Query phải **khớp sát** keyword → reach thấp, relevance cao |

**Exact không chỉ “đúng từng chữ”:** Help ghi exact còn có thể gồm cú pháp gần, **đảo thứ tự từ cùng nghĩa**, thêm/bớt từ chức năng, từ ngầm, **đồng nghĩa / paraphrase**.

**Phrase — quy tắc & ví dụ chính thức:**
- Keyword nên **bằng hoặc rộng hơn** query; intent của query nằm trong phạm vi intent keyword.
- Ví dụ: query `Halston 1-12 perfume` + keyword `"Luxury fragrance"` → match (intent nước hoa luxury; brand cụ thể thuộc nhóm rộng hơn).
- Query nhiều SP song song (`swim shirt and shorts`) + keyword chỉ 1 SP (`Swim short`) → vẫn có thể phrase match vì nghĩa keyword nằm trong query.
- Keyword đa nghĩa (`"LIP"`) + query makeup môi (`ombre lip blush`) → phrase match nếu một intent khớp.

**Khuyến nghị vận hành (Help Search Ads keywords + One-Pager chính thức):**
1. **Launch:** ưu tiên **broad** càng nhiều càng tốt — hẹp quá thì ít impression, thuật toán search khó học.
2. **Sau learning:** đánh giá Search Terms → chuyển keyword tốt sang **phrase/exact** để thu hẹp & scale có kiểm soát; đổi match type được khi campaign đang chạy.
3. Gợi ý ≥ **20** keyword/ad group; tối đa **1.000** keyword, **10.000** negative / ad group.
4. **Negative keywords** (Help setup 12/2025): chỉ thêm **sau khi** campaign đã build & save; 3 tầng — **Account** (global, tối đa **1.000**, mặc định **broad**), **Campaign**, **Ad Group**. Dùng Search Terms để tìm query spam/không liên quan → negative.
5. Keyword-level bid chỉ với objective **Traffic** (Search Ads Campaign).

**Thực dụng VN:**
1. Bundle keyword tiếng Việt theo chủ đề (VD “son môi”, “kem chống nắng”) + creative khớp; launch broad trước.
2. Mỗi vài ngày đọc Search Terms → negative từ khóa rẻ/spam (“miễn phí”, “cách làm”, đối thủ không muốn); account-level cho từ nhạy cảm / luôn loại.
3. Long-tail chuyển phrase/exact sau khi đã có data; đừng exact hết lúc launch.
4. Phân tích hiệu suất theo **ad group/campaign**; báo cáo match type theo keyword chỉ hỗ trợ đầy đủ với Search Traffic (theo Help reporting).

### 28. Đào sâu: Value-based Optimization (VBO) — tối ưu theo giá trị đơn
Học lúc: 2026-10-12 22:38 ICT

**Bản chất:** thay vì mua *nhiều đơn nhất* (goal Purchase/Complete Payment), VBO tìm người có khả năng mua **giá trị cao hơn** → tối ưu tổng giá trị / ROAS.

**VBO cho web (Help, cập nhật 07/2025):**
- Điều kiện mở: ≥ **20** event purchase **có value + currency**, được attribute & unique, trong **7 ngày liên tiếp bất kỳ** (placement TikTok / Pangle / Global App Bundle).
- Gửi value/currency qua Pixel (custom event có parameter), **Events API**, hoặc Event Builder.
- Objective: **Sales → Website**; Optimization event: **Purchase**; Optimization goal: **Value**; hỗ trợ CBO; Android + iOS; mọi thị trường có auction ads.
- Bid strategy: **Highest Value** (tối đa tổng giá trị trong ngân sách) hoặc **Minimum ROAS** (đặt sàn ROAS).

**VBO cho app (Help 05/2026):** objective App promotion; tối ưu Purchase value hoặc Ad revenue value (LTV); bid **Highest Value** hoặc **Target ROAS** (Target ROAS cho Smart+ App, chọn Day 0 ROAS; cửa sổ 7-day click / 7-day engaged view / 1-day view). Xem thêm mục 25 về learning VBO app (≥7 ngày, budget ~30× CPA).

**TikTok Shop:** VBO kiểu cũ (Highest GMV / Min ROAS trong Product Sales) đã được **GMV Max** thay thế — giá trị nằm sẵn trong Target ROI (xem mục 18). Đây là thông tin từ nguồn bên thứ ba (kolvant), khớp với việc GMV Max là loại campaign Shop chính.

**Thực dụng VN:**
1. Web bán hàng giá trị đơn chênh lệch lớn (mỹ phẩm combo, đồ gia dụng) mới đáng dùng VBO; giá đồng đều thì Purchase thường là đủ.
2. Kiểm tra trước: event CompletePayment có **value đúng (VND)** và **currency = VND**, dedupe Pixel + Events API; thiếu value thì VBO không mở.
3. Chưa có mốc ROAS: chạy **Highest Value** trước. Đã có ROAS 7 ngày ổn: dùng **Minimum ROAS**, đặt sàn thấp hơn ROAS thực tế (tip bên thứ ba: ~0,8× ROAS 7 ngày cùng thị trường; sàn quá cao → khó tiêu tiền). Không phải số chính thức của TikTok.
4. A/B: giữ nguyên target/budget/creative, chỉ đổi goal Purchase vs Value; so sánh **AOV (giá trị đơn TB) + ROAS**, không chỉ CPA (VBO thường CPA cao hơn nhưng đơn to hơn).

### 30. Đào sâu: Custom Audience, Lookalike & Smart Targeting
Học lúc: 2026-10-12 23:27 ICT

**Custom Audience (Help, cập nhật 11/2025):** xây đối tượng từ người đã biết / đã tương tác — file khách hàng, hoạt động web/app (Pixel), engagement trên TikTok, hoặc partner kích hoạt. Dùng để: retarget, **exclude** khách mới mua (tiết kiệm ngân sách), seed cho Lookalike.
- Ngưỡng dùng trong ad group: ≥ **1.000** matched users.
- Estimator **Available Audience** khi tạo campaign phản ánh reach thực tế hơn (opt-in, tuổi, location…).

**Nguồn tạo Custom thường dùng:**
1. **Customer File** (Help 09/2025): upload `.csv` / `.txt` — email, phone, MAID (hashed hoặc raw, đúng format). Chỉ reach người đã opt-in. Dùng include (CRM) hoặc exclude (đã mua gần đây).
2. **Engagement** (Help): hành động trên TikTok / ads (xem video 2s/6s/100%, like/share/comment, click/impression ad, xem LIVE…). Lookback: organic/LIVE thường **7/14/30** ngày; Video Ads tới **7–180** ngày. Có Broaden (OR) / Narrow (AND) rules; exclude theo engagement + Ad Group ID. Auto-refresh mặc định bật.
3. Website / App activity qua Pixel hoặc Events API (đã học mục 3) — visitor, add-to-cart, purchase…

**Lookalike Audience (Help, cập nhật 06/2025):** từ Custom seed ≥ **1.000**, thuật toán tìm user tương tự trên thị trường chọn.
- Ba mức: **Narrow** (giống nhất, pool nhỏ), **Balanced**, **Broad** (reach lớn hơn, độ giống vừa). Size phụ thuộc user base thị trường + mức chọn.
- Mục đích chính: **prospecting** (khách mới), không thay retarget.

**Smart Targeting (Help, cập nhật 07/2025):** bật thì hệ thống **có thể** giao ads ngoài Interest & Behaviors hoặc Audience đã chọn nếu dự đoán cải thiện kết quả (giảm CPA, giảm ad fatigue).
- Objective hỗ trợ (auction): Video views, Community interaction, Traffic, Lead gen, App install, Web conversion. **Không** có trên placement Global App Bundle / Pangle.
- **Không** nới age / gender / location.
- Estimator size **không** cập nhật khi bật Smart; khi expand thật sẽ reach ngoài pool ban đầu. Khác Targeting Expansion cũ: UI kiểm soát rõ hơn phần nào được expand; thời điểm expand do model quyết định (không có mốc cố định).

**Thực dụng VN:**
1. Funnel 3 lớp: Cold = Lookalike (Narrow từ purchaser) hoặc Interest + Smart Targeting; Warm = engagement 6s/100% hoặc ATC; Hot = visitor/ATC gần → exclude purchaser 7–30 ngày.
2. Seed Lookalike tốt nhất = purchaser / high-value (CRM file hash phone VN + email) nếu ≥1.000 match; không đủ thì dùng ATC hoặc engagers video ads 30–90 ngày.

**Search Center là gì:** hub trong Ads Manager (**Tools → Search Center**) để quản lý **negative keywords cấp tài khoản** (thêm tay hoặc bulk upload). Đây là chỗ gắn exclusion “toàn account” trước khi tinh chỉnh từng campaign/ad group.

**Negative keywords làm gì:** chặn ads hiện với query tìm kiếm **không liên quan** hoặc hại brand (spam, “miễn phí”, đối thủ, từ nhạy cảm…). Help chính thức: không giao traffic cho query khớp negative đã chọn. Dùng được cho **Search Ads Campaign** và cả **Automatic Search Placement** (in-feed mở rộng sang SRP — không phải keyword targeting tay).

**3 tầng exclusion (Help setup, cập nhật 12/2025):**
1. **Account** (Search Center): exclusion **global** mọi campaign — ví dụ competitor / từ nhạy cảm luôn loại. Tối đa **1.000** keyword; thêm tay hoặc **Upload** theo template. Mặc định match = **broad**.
2. **Campaign**: exclusion theo chủ đề / initiative — vào campaign → **View Data** → panel **Search** → Keywords → **Set Negative Keywords** → upload template.
3. **Ad Group**: tinh chỉnh sát keyword targeting của nhóm — cùng path View Data → Search → Keywords → Set Negative Keywords. Tối đa **10.000** negative / ad group (Help Search Ads keywords, 07/2025).

**Quy tắc vận hành quan trọng:**
- Negative **chỉ thêm được sau khi** campaign đã **build & save** — không gắn lúc tạo draft chưa lưu.
- Nguồn tốt nhất để chọn negative: báo cáo **Search Terms** (query organic khớp keyword/ads) → vừa thêm negative, vừa mở rộng keyword targeting.
- Automatic Search Placement (mặc định **On** khi tạo campaign mới, auction): dùng negative để lọc query xấu trên SRP dù không chạy Search Ads Campaign riêng; delivery search **không đảm bảo** 100% (relevancy, budget, cạnh tranh…).

**Báo cáo Search (để quyết định negative đúng lúc):**
- Custom Reports + **Search Terms**; metric ở ad group / keyword / search term (Cost, Impression, Click, CPC, CTR, Conversion, CVR, CPA…).
- Latency ~**8 giờ**; conversion theo keyword hay chỉ hiện **top conversion keywords**; keyword/search term conversion thấp có thể bị **ẩn** (privacy) → tổng conversion có thể lệch. TikTok khuyên đọc conversion keyword **~3 ngày** sau conversion; tối ưu khi ad group **< 5 conversion** thì tập trung ở **cấp ad group**, không micro-manage từng keyword.
- Không có breakdown creative × search term/keyword (privacy). Match type reporting chỉ đủ với Search **Traffic**.

**Thực dụng VN:**
1. Ngày 1 sau launch Search / bật Automatic Search: mở Search Terms mỗi vài ngày → negative tiếng Việt kiểu “cách làm”, “miễn phí”, “tự chế”, “fake”, tên đối thủ không muốn, ngành nhạy cảm.
2. Account-level (Search Center): list “luôn cấm” (brand safety / chính trị / từ tục) ≤1.000 broad — đỡ phải gắn lại từng campaign.
3. Ad group-level: negative theo bundle chủ đề (VD ad group “kem chống nắng” loại “kem dưỡng trắng” nếu không bán).
4. Đừng nhồi negative lúc launch khiến impression chết — ưu tiên broad keyword trước (đã học mục 27), negative sau khi có Search Terms thật.
5. Phân biệt: Search Ads Campaign = keyword tay + negative; Automatic Search Placement = tái dùng creative/target in-feed lên SRP + negative lọc query.

### 36. Đào sâu: Brand Lift Study (và Conversion Lift Study liên quan)
Học lúc: 2026-10-13 01:11 ICT

**Brand Lift Study (BLS) — Help Center, cập nhật 09/2026:**
- Thí nghiệm chạy song song với nội dung được tài trợ để đo **tác động thương hiệu tăng thêm (incremental)** trên TikTok.
- Có thể gắn **một campaign** hoặc **toàn bộ** nội dung được promote trên TikTok.
- **Chỉ Account Manager (AM) mới setup được** — không tự bật trong Ads Manager như Split Test thường.

**Cách đo:** TikTok random một phần audience mục tiêu thành 2 nhóm:
- **Exposed**: thấy ad của bạn
- **Control**: không thấy ad
So sánh KPI (awareness, ad recall…) bằng polling + thống kê → phần chênh lệch gán cho quảng cáo.

**Lợi ích chính thức nêu:**
1. Baseline awareness thương hiệu trên TikTok
2. Sponsored content có kéo purchase intent không
3. Creative nào resonate nhất với audience mục tiêu

**Lưu ý setup (chính thức):**
- Câu hỏi survey phải khớp creative + điều muốn học về brand/product
- Nên **gồm tất cả campaign TikTok đang chạy** vào study
- Gửi AM **Campaign ID** các campaign gần đây để Control chưa từng thấy ad (tránh nhiễm)

**Conversion Lift Study (CLS) — đo incremental conversion (liên quan):**
- Trả lời: ad TikTok có mang **tăng trưởng chuyển đổi thực** không (không chỉ attribution last-click).
- Cũng random test vs control; đo incremental conversions / lift %.

### 39. Đào sâu: Vì sao có nhấp mà 0 tin nhắn (click ≠ Conversation)
Học lúc: 2026-10-13 01:53 ICT

**Click và Conversation là hai bước khác nhau:**
- **Click / CTR**: user bấm CTA trên ad → hệ thống mở khung chat DM với Business Account (Identity).
- **Conversation (Results khi goal = Conversations)**: chỉ đếm khi có **cuộc trò chuyện** thực sự (user bắt đầu chat), không phải mỗi lần mở khung chat. Vì vậy CTR > 0 mà Results = 0 là tình huống phổ biến, không có nghĩa Ads Manager “hỏng”.

**Checklist nguyên nhân (theo thứ tự kiểm tra official):**

1. **Quyền nhận DM chưa = Everyone (bắt buộc để chạy Direct Messaging Ads)**  
   App: Profile → ☰ → Settings and privacy → Privacy → Direct Messages → Allow direct messages from = **Everyone**.  
   Hoặc trong Ads Manager lúc chọn Identity: nếu account chưa đủ quyền → hover → Set up → tick cập nhật DM = Everyone.  
   Không mở = user bấm vào nhưng **không gửi được tin** → 0 Conversation.

2. **Sai Identity / Business Account nhận inbox**  
   Ad gắn account A nhưng bạn nhìn inbox account B → tưởng “0 tin”. Phải khớp đúng account gắn ở tầng Ad.

3. **Thiếu hoặc Welcome Message chưa duyệt**  
   Setup DM Ads: phải **Create or attach Welcome Message**.  
   Auto messages (Welcome / Suggested questions / Keyword reply / Chat prompts) chỉ có trên account **Advanced Access** hoặc **Verified Business Account**; General account không có.  
   Welcome tối đa **250 ký tự**, submit → duyệt **1–5 ngày làm việc**; đang chờ duyệt / bị từ chối → chat trống, user thoát không nhắn.  
   Điều kiện: “Receive messages from Everyone” phải bật mới dùng Automatic Message.

4. **Caption / CTA không nói rõ “nhắn tin”**  
   Official: text phải làm rõ bấm CTA sẽ mở **direct message chat**. Blog TikTok: dùng thống nhất “Message us” / “Get in touch” trên creative + caption. Soft CTA kiểu “xem thêm / tìm hiểu” → nhiều click tò mò, ít người chịu gõ tin đầu.

5. **Đang nhìn nhầm cột “Conversions” (pixel/web) thay vì Messaging → Conversations**  
   Đã học mục 38: [thương hiệu] báo “0 chuyển đổi” có thể là cột sai. Mở Custom columns → Messaging.

6. **Volume learning còn mỏng**  
   [thương hiệu]: ~10k impression / 22 click / CTR 0.21%. Số click nhỏ → dễ 0 Conversation theo xác suất; chưa đủ để kết luận creative chết.

7. **Phản hồi chậm sau khi đã có tin (ảnh hưởng giữ hội thoại, không phải nguyên nhân 0 tin đầu)**  
   Blog TikTok (internal data 2024): trả lời trong **3 phút** → tới **2.2×** conversation engagement rate. Cách: chạy trong giờ có người trực + Welcome Message Template / Messaging Partner. (Số của TikTok, không phải benchmark VN.)

**Thực dụng [thương hiệu] (22 click, 0 Conversation):**
1. App TikTok Business Account đúng Identity → Privacy → DM = **Everyone**.
2. Ads Manager → Ad → có Welcome Message gắn và **đã Approved** (không Pending).
3. Custom columns → Messaging → Conversations started; đối chiếu inbox thật cùng account.
4. Sửa caption/CTA thành kiểu “Nhắn tin ngay để tư vấn / inbox để lấy giá” — khớp offer trong video (policy: creative và nội dung chat không được lệch sản phẩm).
5. Giữ campaign học thêm nếu checklist trên OK; chỉ pause khi inbox cũng 0 sau khi đã sửa quyền + welcome + CTA.

Phải luôn có **phương thức chính hợp lệ**, không thì phân phối có thể bị gián đoạn. **Không dùng thẻ prepaid** cho autopay. Thêm thẻ sẽ bị trừ thử **≥ $10 (hoặc tương đương)** và hoàn trong 15 ngày.
- Ad account thuộc Business Center → chỉ thêm phương thức autopay **trong Business Center**.
- Xem/đổi: Ads Manager > Tools > Settings > Billing > Payment > **My billing option** (có thể không mở cho mọi tài khoản). Help ghi chuyển từ Manual sang Automatic được nhưng không chuyển ngược lại (đoạn này trích từ trang tổng hợp, nên kiểm tra lại trong tài khoản).

**Hóa đơn ở VN (nguồn bên thứ 3, chưa xác minh từ TikTok):**
- Muốn nhận hóa đơn VAT: khai đúng **mã số thuế + thông tin billing doanh nghiệp** trong Business Center; tải ở Business Center > Finance > Invoices (hoặc Billing > Transaction history).
- Invoice có thể sinh theo ngày bill, theo threshold hoặc sau mỗi lần nạp → đối soát theo giao dịch thực tế, không theo "tháng chạy".
- Một số site VN nói TikTok thu VAT 5% từ 1/11/2023 và trừ khi nạp (số dư khả dụng = sau thuế) — **chưa thấy nguồn chính thức TikTok xác nhận**, tự kiểm tra ở Finance > Transactions > Cost.

### 72. Đào sâu: Available Audience / Audience Size Estimation + Broad Targeting
Học lúc: 2026-10-13 07:01 ICT

**Audience Size Estimation là gì (Help, cập nhật 09/2025):**
- Công cụ ước lượng **quy mô đối tượng tiềm năng** theo targeting + placement đã chọn, dựa trên số người từng được hiện ads trên app TikTok trong **30 ngày** gần nhất.
- Nằm **phía trên Reach Estimator** trong Ads Manager khi tạo/sửa Ad Group.
- Ước lượng theo **user account**, không phải dân số thật; **không** dự báo reach/số người campaign sẽ chạm (đó là việc của Reach Estimator).
- Custom Audience mới tạo/sửa trong **24 giờ** có thể làm estimate lệch tạm thời.

**Chỉ báo kích thước (indicators):**
1. **Too Narrow / Narrow**: quá nhỏ → hiệu suất biến động mạnh; nên nới tiêu chí (bỏ interest chồng chéo, mở tuổi/location).
2. **Balanced**: mức phù hợp.
3. **Fairly Broad**: khá lớn → có thể thêm tiêu chí nếu muốn nhắm hơn; nhưng TikTok **khuyến khích** mức này cho performance.

**Available Audience vs Custom Audience (Help Custom Audiences, 11/2025):**
- Custom Audience cần ≥ **1.000 matched users** mới gắn Include/Exclude được.
- Ô **Available Audience** khi dùng Custom Audience cho thấy reach **thực tế hơn** sau khi lọc opt-in, tuổi, location… (không chỉ số matched thô).

**Broad Targeting (Best practices Targeting + Blog Performance Fundamentals):**
- "Fairly Broad" = ước lượng cover **>80%** potential users trong nước đã chọn.
- TikTok nêu (theo test nội bộ, Blog Fundamentals): Fairly Broad trung bình **CPA thấp hơn ~15%**, **conversion rate cao hơn ~20%** so audience hẹp hơn — đây là số liệu họ công bố, không phải benchmark [thương hiệu].
- Audience **quá hẹp** → khó thoát Learning Phase, dễ creative fatigue; chỉ hẹp khi thật sự cần (vd. vài zip) hoặc đã validate bằng test.
- Bật **Smart Targeting** khi dùng Interest & Behavior / Audience: hệ thống có thể giao ngoài selection nếu dự đoán tốt hơn; **không** vượt Age/Location đã khóa. Audience Size Estimation **không cập nhật** khi bật Smart Targeting — vẫn hiện size theo selection ban đầu.

**Khác Reach Estimator:**
- Audience Size = pool tiềm năng (account).
- Reach Estimator = dự báo reach/impression theo ngân sách/bid (không dùng Audience Size để đo dân số hay so sánh third-party 1:1).

**Thực dụng [thương hiệu] (DM Conversations, CTR 0,21%, 0 tin nhắn, ~167k VND):**
1. Mở Ad Group [thương hiệu] → nhìn **Available Audience indicator**. Narrow/Too Narrow → nới: bỏ interest chồng, mở tuổi, đừng khoanh location quá chặt (mục 70). Fairly Broad/Balanced là mục tiêu lúc learning.
2. Đừng siết Interest + Exclude nặng lúc đang 0 conversation (mục 69) — thu hẹp làm learning khó hơn.
3. Giữ **Age + Location** đúng khu vực khách BĐS; bật Smart Targeting nếu đang dùng Interest/Behavior.
4. Có Custom Audience exclude: xem Available Audience sau khi gắn — nếu tụt mạnh về Narrow thì tạm bỏ Exclude.
5. Audience Size lớn ≠ sẽ có tin nhắn: vẫn cần creative/CTA/Welcome/DM mở (mục 39–43). Indicator chỉ nói pool đủ để hệ thống học, không thay creative.

### 73. Đào sâu: Delivery type (Standard vs Accelerated) + Daily vs Lifetime budget + nhịp tăng ngân sách

**Delivery type (Glossary + Budget help, chính thức):**
- **Standard Delivery**: hệ thống rải ngân sách đều theo lưu lượng trong khoảng thời gian chạy (giờ đông traffic thì phân phối nhiều hơn) → ổn định, hợp cho learning.
- **Accelerated Delivery**: tiêu ngân sách & lấy kết quả **nhanh nhất có thể**; hợp cho promo/sự kiện gấp. Theo nguồn bên thứ ba (Tabcut) chỉ đi với daily budget — chưa xác nhận trên trang chính thức.

**Daily vs Lifetime (About Budget, chính thức):**
- Daily = mức trung bình/ngày, hợp chiến dịch chạy liên tục, theo dõi chỉnh hằng ngày. Lifetime = tổng cho cả thời gian, hợp chiến dịch có hạn cố định.
- **Không đổi được loại ngân sách** (daily ↔ lifetime) sau khi campaign/ad group đã chạy → muốn đổi phải tạo mới.
- Ngân sách Campaign **không được thấp hơn** Ad Group (gây lỗi phân phối). Ad group hết ngân sách → tự dừng.
- Ngưỡng tối thiểu (FAQ, tính bằng USD): campaign $50, ad group $20/ngày. Tài khoản VND có thể quy đổi khác → xem cảnh báo ngay trong Ads Manager, không tự đoán.
- FAQ khuyên campaign để **No Limit** để ngân sách không cản hệ thống tìm đối tượng; nếu Cost Cap/Target CPA mà không tiêu hết tiền → bid quá thấp, nâng bid hoặc chuyển Maximum Results.

**Nhịp tăng ngân sách (About Budget, cập nhật mới):**
- Đang **learning**: mỗi lần tăng **≤ 40%**; đã thoát learning: **≤ 30%**; **không chỉnh dày hơn 2 ngày/lần**. (User Guide PDF cũ ghi ≤50% — ưu tiên trang help mới.)

**Thực dụng [thương hiệu]:**
1. Để **Standard Delivery** + **Daily budget** ở Ad Group (đang learning, 0 tin nhắn → cần ổn định, không cần đốt nhanh).
2. Campaign budget để No Limit hoặc ≥ ngân sách ad group, tránh lỗi phân phối.
3. Đừng tăng ngân sách khi còn 0 Conversation — sửa creative/CTA/Welcome trước (mục 39–43). Khi đã có tin nhắn đều, tăng ≤40%/lần, cách nhau ≥2 ngày.
4. Nếu dùng Cost Cap mà tiêu không hết → chuyển Maximum Results (mục 42).

### 74. Đào sâu: Duplicate campaign Manual → Smart+ (Lead gen / DM) — khi nào và giữ gì
Học lúc: 2026-10-13 07:56 ICT

**Tính năng (Help chính thức, cập nhật 10/2026):** trong Campaign List, icon **Duplicate** có thể nhân bản campaign Manual (hoặc Smart+) sang **Upgraded Smart+**, giữ phần lớn cấu trúc / targeting / creative. **Chưa roll-out hết account** — nếu không thấy prompt Smart+, hỏi Support / AM.

**Lead generation — khác Sales:**
- Khi Duplicate Lead gen Manual: pop-up cho chọn **update sang Smart+** hoặc **nhân bản vẫn Manual** → Confirm.
- Split test bật ở bản gốc → **bị xóa** khi copy sang Smart+.
- CBO: ngân sách/bid có thể **reset để review lại**; mọi ad group trong CBO Smart+ phải cùng optimization location, goal, event, target CPA.

**Budget & Schedule khi copy (bảng Help):**
- Schedule (start continuous / start–end + timezone) **giữ nguyên**.
- **Dayparting** (All day / Select specific time) **giữ nguyên**.
- Placement giữ; nếu Advertiser ID không trong allowlist Ad Network → hệ thống có thể ép **TikTok Only**.

**Riêng Lead gen — Optimization giữ:**
- TikTok direct messages: **Goal + Attribution settings** giữ.
- Instant messaging apps: Goal + Message event set + Attribution giữ.
- Instant form / Website / Phone call: tương ứng giữ theo bảng Help.

**Audience khi lên Smart+ (Lead gen):**
- Location giữ; Minimum age: nếu Manual ≥25 → Smart+ dùng 25+, không thì mặc định **18+**.
- Exclude audience / language giữ. Gợi ý Age/Gender/Interest giữ; chi tiết thêm chỉ khi **chuyển sang manual targeting**.
- Mặc định Smart+ chạy **automatic mode** trừ khi bạn chủ động chuyển manual.

**Bidding khi lên Smart+:**
- Daily budget: hỗ trợ Lowest Cost (Maximum Delivery) **và** Cost Cap.
- Lifetime budget: **chỉ** Lowest Cost — nếu Manual dùng Cost Cap + Lifetime → field bid **reset** để nhập lại.
- Non-CBO: mọi ad group phải cùng bidding strategy; lệch nhau → reset trống.

**Ad level:** creative / interactive add-on / Instant Form / IM app gần như giữ; **CTA chuẩn nâng lên Dynamic CTA**. Instant Page ad group **không** được duplicate (Sales).

**Thực dụng [thương hiệu] (Manual, Conversations DM, ~167k VND, 0 tin nhắn, đang learning):**
1. **Đừng Duplicate sang Smart+ chỉ vì 0 conversation** — trước hết sửa checklist mục 39–43 (DM Everyone, Welcome, Identity, creative CTA inbox). Duplicate = campaign mới, learning lại từ đầu.
2. Khi checklist OK mà vẫn chậm / muốn thử Smart+: Duplicate [thương hiệu] → chọn **Smart+** (Lead gen) → kiểm Goal vẫn **TikTok direct messages → Conversations**, Identity đúng account inbox, Welcome còn gắn, dayparting giờ trực (nếu đã set).
3. Sau Duplicate: rà Bid — nếu Lifetime + Cost Cap bị reset, chuyển **Daily + Maximum Delivery** lúc learning (mục 42, 73).
4. Split test trên bản cũ sẽ mất — [thương hiệu] chưa cần split (mục 56).
5. Giữ bản Manual cũ chạy song song ngắn rồi tắt dần, hoặc pause Manual trước khi bật Smart+ để tránh 2 ad group cùng đấu 1 audience nhỏ.
